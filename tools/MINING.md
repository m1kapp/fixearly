# O(n²) 채굴 파이프라인

fixearly의 O(n²) 축은 등급을 매기지 않는다(진단 전용). 대신 **PR 가능한 결함 후보**를 뽑는다.
`--mine` 은 그 후보 전체를 손검증용으로 덤프한다.

```bash
npx fixearly --dir=<backend-src> --mine
# 콘솔에 [zone] recv.method() — file:line (loop: ...) 전체 출력
# <out>/quadratic-candidates.json 에도 저장
```

## 랭킹 근거

같은 O(n²)라도 PR 가치는 천차만별이다. 두 신호로 거른다:

- **zone** (파일 경로): `backend`(api/server/services/routes/…) > `other` > `frontend`(.tsx·components) > `test`.
  프론트 UI 루프는 n이 메뉴·필터 수준(유계)이라 "마이크로옵트"로 거절당한다. 백엔드는 n이 요청·행(무계).
  `api/admin/*.route.ts` 같은 REST 라우트가 `/admin/` 때문에 프론트로 오분류되지 않게 backend 를 먼저 매칭한다.
- **무계 반복**: 루프 반복대상이 배열 리터럴이면 유계, 식별자·프로퍼티·호출이면 유저데이터 개연 → 후보.

후보 = `zone ∉ {test, frontend}` 이면서 무계 반복. 이게 `--mine` 이 뱉는 목록이다.

## 손검증(⑥)은 여전히 필수

`--mine` 은 후보만 좁힌다. 실제 PR 전에 상위 몇 건을 직접 읽어 **진짜 O(n²)에 무계 n인지**,
**Map/Set으로 안전히 고쳐지는지**(first-match 보존 등)를 확인한다. 정적 신호는 후보일 뿐이다.

그래서 이 도구의 정직성 강제장치는 여전히 "PR로 낼 수 있나 / 머지되나"이지, 후보 개수가 아니다.
