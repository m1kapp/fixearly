How the rules get hardened.

01

남이 이미 고친 걸 읽는다

Read what others already fixed

머지된 성능 PR 909건을 긁어 형태로 묶는다. 무엇이 실제로 고쳐지는지가 거기 있다 — 그리고 기계로 잡을 수 있는 건 5%뿐이라는 것도.

We mine 909 merged performance PRs and group them by shape — what actually gets fixed, and that only 5% is mechanizable.

02

남의 코드에 걸어본다

Run it on strangers' code

규칙 후보를 오픈소스 74곳(진단 검증 코퍼스)에 걸고 걸린 자리를 하나씩 손으로 연다. 쓰기만 하는 컬렉션 은 15건 전부 진짜여서 올렸고, 해제할 수 없는 등록 은 16건 중 1건만 진짜라 떨어뜨렸다.

Candidate rules run against 74 open-source repos; every hit gets opened by hand. write-only collection was 15/15 real and shipped; unremovable registration was 1/16 and got dropped.

03

직접 내본다

Submit it ourselves

규칙이 짚은 자리를 PR 로 낸다. 남의 저장소 메인테이너가 받아주거나 거절한다. 우리가 꾸밀 수 있는 숫자가 아니다 — 머지는 못 조작한다.

We open PRs for what the rules flag. A stranger's maintainer merges it or turns it down. It's not a number we control — a merge can't be faked.
